# AALL — aptX Adaptive Low Latency для Sennheiser MOMENTUM 4

*Русское зеркало [README.md](../../README.md) (основной, английский). При расхождении
основным источником истины считается английская версия.*

AALL заставляет Bluetooth-наушники Sennheiser MOMENTUM 4 разговаривать с
Linux-компьютером через кодек **aptX Adaptive** (в первую очередь в режиме Low
Latency) через собственный Bluetooth-адаптер компьютера — без USB-донглов и без
телефона-посредника. Командная утилита и демон, которые устанавливает AALL,
называются `momentum4`.

## Что это и для кого

AALL — набор из трёх частей, которые вместе дают Linux-компьютеру возможность
разговаривать с наушниками на кодеке aptX Adaptive (в первую очередь в режиме
Low Latency) напрямую через PipeWire/WirePlumber:

1. **Плагин** для WirePlumber/PipeWire (SPA bluez5) — добавляет кодек `aptx_adaptive`
   в список кодеков, которые PipeWire предлагает Bluetooth-наушникам при подключении.
2. **Энкодер** — проприетарный DSP-модуль Qualcomm (Hexagon ADSP), запускаемый под
   пользовательской эмуляцией QEMU (без телефона, без прошивки, без root). Модуль не
   входит в поставку AALL — см. «Требования» и `docs/user/obtaining-encoder.ru.md`.
3. **Демон и CLI `momentum4`** — установка/включение/выключение, диагностика,
   звонки и жесты наушников, единый конфиг.

Разрабатывалось и проверялось на Sennheiser Momentum 4. По конструкции подходит
любым наушникам с типовым заводским профилем возможностей "stereo headset", который
декларируют многие чипы Qualcomm с поддержкой aptX Adaptive — по умолчанию плагин
включает кодек только для устройств с этим отпечатком (`[adaptive] allow-devices =
adk-stereo`), чтобы не затрагивать чужие гарнитуры со своим собственным (возможно
несовместимым) набором параметров Adaptive. Точный список MAC-адресов или полное
снятие фильтра — тоже поддерживаются, см. «Настройка».

**Если у вас нет наушников с aptX Adaptive** или вы не хотите разбираться с
DSP-модулем — этот проект вам не нужен: без модуля кодек просто не появляется, и
наушники работают как обычно (aptX HD/aptX/SBC — что они умеют сами).

## Почему я это сделал

Меня достали проводные наушники, а потом и беспроводные, которые дают низкую
задержку только через USB-донгл, — донглы ломаются, теряются и перестают работать.
Я захотел большего: наушники, которые подключаются прямо к Bluetooth ноутбука и при
этом успевают за быстрым скринридером. Теперь есть AALL — aptX Adaptive Low Latency
под Linux.

## Статус и поддерживаемые системы

| компонент | версия | как проверить |
|---|---|---|
| дистрибутив | Debian 12 (bookworm) | проверено; другие дистрибутивы с той же версией PipeWire, вероятно, тоже подойдут, но не проверялись |
| PipeWire | 1.4.2 | `pipewire --version` / `pkg-config --modversion libpipewire-0.3` |
| WirePlumber | любая, совместимая с PipeWire 1.4.2 | `wireplumber --version` |
| ядро | любое современное (6.x) с поддержкой вашего Bluetooth-адаптера | — |
| Bluetooth-стек | BlueZ 5.6x | `bluetoothctl --version` |

По умолчанию плагин включает кодек только для отпечатка возможностей Sennheiser
MOMENTUM 4, описанного выше. Другие наушники на чипах Qualcomm с тем же заводским
профилем stereo-гарнитуры тоже ожидаемо должны работать, но автором не проверялись.

Плагин собирается и патчится ровно против PipeWire 1.4.2 (см. `module/SUPPORTED`).
Если у вас другая версия PipeWire — сборка откажется с понятным сообщением; после
обновления PipeWire нужно пересобрать и переустановить плагин (`make module && make
install`).

## Как это работает

```
приложение → PipeWire → SPA-плагин bluez5 (наш кодек aptx_adaptive)
           → помощник (qemu-hexagon + DSP-модуль) → сжатые кадры
           → AVDTP (Bluetooth A2DP) → наушники
```

Плагин регистрирует кодек `aptx_adaptive` в списке кодеков, которые PipeWire
предлагает через AVDTP при подключении наушников. Если наушники поддерживают
Adaptive и приняли конфигурацию — PipeWire начинает кодировать этим путём вместо
штатного aptX HD/SBC.

Два режима покрывают две реальные потребности от Bluetooth-гарнитуры:

- **AALL** (aptX Adaptive Low Latency, A2DP) — режим по умолчанию, для любого
  прослушивания, включая экранного диктора.
- **Режим звонка** (HFP, mSBC с фоллбэком на CVSD) — включается автоматически (или по
  команде), когда приложению нужен микрофон наушников, поскольку у профиля A2DP
  aptX Adaptive обратного аудиоканала попросту нет. См. «Звонки и жесты».

По умолчанию один жест переключает между ними (свайп вперёд на наушниках включает
режим звонка; собственный жест наушников «повесить трубку», отправляемый как
команда `AT+CHUP` по HFP, возвращает в AALL), а кнопка на самих наушниках
включает/выключает микрофон во время звонка. Всё это переназначается через
`[control]` в `momentum4.conf` — см. «Настройка».

### QEMU и при чём тут (не при чём) KVM

DSP-модуль скомпилирован для архитектуры Hexagon (QDSP6), а не для x86_64. Чтобы его
запускать на обычном компьютере, AALL использует **QEMU в режиме пользовательской
эмуляции** (`linux-user`, движок TCG — программный JIT-транслятор кода): один процесс
`qemu-hexagon` транслирует инструкции Hexagon в x86-64 на лету и исполняет только
этот один модуль, не всю операционную систему.

Это **не виртуальная машина**: ядра гостевой ОС нет, диска нет, `/dev/kvm` не
используется и не может быть использован — KVM ускоряет виртуализацию **той же**
архитектуры (x86-на-x86), а здесь транслируется **другая** архитектура (Hexagon на
x86-64), для чего аппаратного ускорения в принципе не существует. Загрузка на ядро —
единицы процентов (измерено: ≈6% одного ядра для свежего QEMU, собранного из
исходников; системный `qemu-user-static` из репозитория Debian медленнее, но тоже
работает).

Более подробное объяснение всего конвейера — `docs/user/HOW-IT-WORKS.ru.md`
(`docs/user/HOW-IT-WORKS.md` на английском).

## Требования

Сборочные зависимости (только для сборки, не для работы) на Debian 12:

```
# common + демон/CLI + loader (`make`)
sudo apt install meson ninja-build pkg-config gcc clang lld \
    libpipewire-0.3-dev libsystemd-dev

# плагин WirePlumber/PipeWire (`make module`) -- PipeWire патчит и
# пересобирает bluez5 из исходников, поэтому нужны заголовки ВСЕХ
# кодеков/библиотек, которые оно поддерживает, не только aptX:
sudo apt install libdbus-1-dev libbluetooth-dev libsbc-dev libopus-dev \
    libusb-1.0-0-dev libldacbt-enc-dev libldacbt-abr-dev \
    libfreeaptx-dev liblc3-dev libglib2.0-dev
```

`libpipewire-0.3-dev`/`libspa-0.2-dev` версии **≥1.4.2** на Debian 12 (bookworm)
**не входят в основной репозиторий** (там 0.3.65) — их нужно ставить из
`bookworm-backports`:

```
echo "deb http://deb.debian.org/debian bookworm-backports main" | \
    sudo tee /etc/apt/sources.list.d/bookworm-backports.list
sudo apt update
sudo apt install -t bookworm-backports pipewire wireplumber \
    libpipewire-0.3-dev libspa-0.2-dev
```

(без этого шага `meson setup` для демона не найдёт кандидата, подходящего под
`-Dpipewire_min_version`.)

Для энкодера дополнительно нужен `clang` с поддержкой цели Hexagon (обычно есть в
пакете `clang`/`clang-<версия>` начиная с версии 14, уже включён выше) и `lld`.
Сборка собственного `qemu-hexagon` — необязательный шаг, см. `qemu/README.md`.

### Проприетарный DSP-модуль (обязателен для звука через Adaptive)

aptX Adaptive реализован в проприетарном модуле Qualcomm
(`capi_v2_aptX_CLHDADV_Encoder.so`), частью прошивки ADSP некоторых
Android-телефонов на Snapdragon. AALL **не распространяет и не может
распространять** этот файл — его нужно найти самостоятельно в прошивке устройства, к
которому у вас есть законный доступ. Пошаговая инструкция — `docs/user/obtaining-encoder.ru.md`.
Без этого файла всё остальное работает как обычно, просто кодек Adaptive не
появляется (наушники используют то, что умеют без него).

## Сборка

```
git clone <URL> aall && cd aall
make               # common + демон/CLI + loader (для DSP-модуля)
make module        # плагин WirePlumber/PipeWire (нужна сеть один раз -- тарбол PipeWire 1.4.2)
make qemu          # (опционально) свой qemu-hexagon; без этого шага можно
                    # использовать системный qemu-user-static, он медленнее
make check         # тесты (common + демон; плагин тестируется отдельно, см.
                    # комментарий в заголовке каждого module/test/*.c)
```

`make` без аргументов не трогает сеть, если модуль и qemu вам пока не нужны (например,
для разработки самого демона), и сразу СОБИРАЕТ (не только печатает справку) —
`make help` печатает список целей выше, ничего не строя. Подробности и опции сборки —
`meson_options.txt` (`-Ddev_build`, `-Dhexagon_cc`, `-Dpipewire_min_version`).

Если `clang` без поддержки цели Hexagon (или отсутствует) — сборка `loader`
завершится понятной ошибкой с названием недостающего пакета, а не молчаливым
провалом.

## Установка

```
make install PREFIX=/usr/local     # системная установка (нужен sudo/права на PREFIX)
# или, без прав root:
make install PREFIX=$HOME/.local
```

Дальше настройте DSP-модуль (см. выше) и подключите всё через `momentum4`:

```
momentum4 setup --capi /путь/к/capi_v2_aptX_CLHDADV_Encoder.so   # см. docs/user/obtaining-encoder.ru.md
momentum4 install               # сухой прогон по умолчанию -- покажет план и ничего не изменит
momentum4 install --yes         # применяет: конфиг, overlay WirePlumber, юниты (без запуска)
momentum4 enable --yes          # запускает всё и перезапускает WirePlumber -- звук прервётся на пару секунд
```

`momentum4 install` без `--yes` **не меняет систему** — только показывает, что именно
будет сделано (обновление `momentum4.conf`, файл-переопределение для WirePlumber,
включение systemd-юнитов). `momentum4 enable` — единственная команда, которая
перезапускает WirePlumber (это нужно, чтобы он подхватил новый плагин) и поэтому
на секунду-другую прерывает звук на **всех** устройствах, не только на ваших
наушниках; предупреждение выводится перед выполнением.

Подключите наушники после этого обычным образом (через `bluetoothctl` или апплет
вашего рабочего стола) — если модель поддерживается и DSP-модуль на месте, PipeWire
предложит ей кодек `aptx_adaptive`.

## Включение и отключение

- `momentum4 enable [--yes]` — включить (запускает юниты, перезапускает WirePlumber).
- `momentum4 disable [--yes]` — откатить: остановить наши юниты, убрать
  переопределение WirePlumber, перезапустить WirePlumber. Наушники возвращаются на
  обычный кодек (обычно aptX HD), который они поддерживали и раньше. Это самый
  быстрый способ вернуть звук к прежнему поведению, если что-то работает не так.
- `momentum4 uninstall [--purge] [--yes]` — `disable` и дополнительно убрать
  установленные ссылки на юниты; с `--purge` — ещё и `momentum4.conf`, и вашу копию
  DSP-модуля (только ту, что положила туда сама `momentum4 setup --capi`).

Обе команды (`enable`/`disable`) по умолчанию делают **сухой прогон**: печатают план
и предупреждение про перезапуск WirePlumber, ничего не меняя, пока не указан `--yes`.

## Звонки и жесты

Демон `momentum4` (запускается как systemd `--user`-сервис) умеет:

- отвечать на входящий вызов управлением HFP/RFCOMM для наушников, которые сами не
  подключены к телефонному приложению (`AT+CHUP`/`ATA`/`BLDN`/`BVRA` и аналогичные
  команды HFP-гарнитуры);
- показывать состояние воспроизведения наушникам через собственный
  MPRIS-плеер в BlueZ, чтобы жесты «пауза»/«трек вперёд-назад» и т. п. на самих
  наушниках доходили до реального плеера на рабочем столе (через MPRIS-проброс);
- восстанавливать HFP/SCO-соединение и микрофон после сбоев без ручного
  переподключения.

Всё это настраивается через секции `[hfp]`/`[control]`/`[automode]` в `momentum4.conf`
(см. ниже) и по умолчанию действует **только** на устройство, определённое как ваши
наушники (`[device] address`/`name-match`) — не на любую HFP-гарнитуру в радиусе
действия.

## Настройка

Один файл, INI с секциями: `~/.config/momentum4/momentum4.conf` (пользовательский,
выше системного `/etc/momentum4/momentum4.conf`, выше поставляемых значений по
умолчанию). Полный, полностью закомментированный список всех ключей с описанием —
не нужно искать в исходниках:

```
momentum4 config defaults          # печатает справочник в stdout
momentum4 config defaults > ~/.config/momentum4/momentum4.conf   # как отправная точка
momentum4 config show              # что реально применяется сейчас и почему (файл:строка)
momentum4 config validate          # проверка синтаксиса/диапазонов без применения
```

Изменения в секциях `[adaptive]`/`[helper]`/`[stats]` подхватываются при следующем
подключении наушников (не нужен перезапуск WirePlumber); `[hfp]` — почти сразу;
`[daemon]`/`[call]`/`[control]`/`[earcon]`/`[automode]` — по команде `momentum4 reload`;
`[graph]` — перезапуском `momentum4-graph.service`. Подробно — в самом справочнике
(`momentum4 config defaults`), у каждого ключа указано, когда он применяется.

Самые вероятные правки для нового пользователя:
- `[adaptive] mode` (`ll0`/`ll1`) и `latency-adjust-ms` — компромисс задержка/устойчивость,
  подбирается на слух;
- `[adaptive] allow-devices` (`adk-stereo` по умолчанию, `any`, или список MAC через
  запятую) — если ваши наушники не распознаются по типовому профилю возможностей stereo-гарнитуры;
- `[hfp] call-control`/`sco-restore` — включить/выключить автоматику звонков;
- `[graph] combine`/`mic-placeholder` — если хотите один комбинированный вывод на
  несколько устройств или постоянный виртуальный микрофон;
- `[general] language` (`en` по умолчанию, или `ru`) — язык вывода CLI (`--help`,
  `status`/`doctor`/`stats`/`config`/`log`) и сообщений демона в journal. Включить
  русский:
  ```
  momentum4 config set general.language ru
  momentum4 reload
  ```
  (или `systemctl --user restart momentum4d`, если демон запущен как юнит; разовая
  команда CLI и так перечитывает ключ заново при каждом запуске).

### Перенос со старой раскладки (два отдельных файла)

Если у вас остался старый `momentum4.conf` без секций и/или отдельный
`aptx-adaptive.conf`:

```
momentum4 config migrate            # сухой прогон -- покажет, что перенесётся
momentum4 config migrate --apply    # переносит, делает резервные копии *.v0.1 рядом
```

## Диагностика

```
momentum4 doctor     # только чтение: версия PipeWire, DSP-модуль и его sha256,
                      # qemu/loader, юниты, overlay -- и явно указывает, если
                      # что-то ссылается на путь разработки, а не на релизную установку
momentum4 stats       # метрики моста энкодера (задержка, недоборы/переполнения буфера)
momentum4 stats --json --history 50
momentum4 log -n 100 --follow   # последние записи momentum4 в journald
momentum4 status      # краткая сводка: подключены ли наушники, каким кодеком
```

`doctor` никогда ничего не чинит и не перезапускает — только показывает, что не так,
и что с этим делать. Он **не проверяет** состояние speech-dispatcher/экранного
диктора (см. раздел «Доступность» ниже) — это вне его зоны ответственности.

Конкретные проблемы и их решения — `docs/user/TROUBLESHOOTING.ru.md`
(`docs/user/TROUBLESHOOTING.md` на английском).

## Удаление

```
momentum4 uninstall --purge --yes
make uninstall PREFIX=...     # убирает то, что установил `make install`
```

После `disable`/`uninstall` наушники используют тот кодек, который выбрали бы без
AALL — никаких изменений в самой прошивке наушников или BlueZ не остаётся.

## Доступность (для пользователей экранного диктора)

Этот проект изначально делался в первую очередь ради задержки и разборчивости речи
экранного диктора (Orca/speech-dispatcher) через Bluetooth-наушники, поэтому здесь
несколько вещей сделаны специально:

- **Команды `install`/`enable`/`disable`/`uninstall` — сухой прогон по умолчанию.**
  Ни одна не тронет звук, пока вы явно не добавите `--yes`. Перед любым действием,
  которое может прервать звук (перезапуск WirePlumber — `enable`/`disable`), команда
  сначала печатает предупреждение об этом.
- **Если что-то пошло не так и звук пропал** — самая короткая команда возврата:
  ```
  momentum4 disable --yes
  ```
  Она останавливает нашу часть и возвращает наушники к их обычному кодеку. Если у вас
  нет доступа к текстовому выводу в этот момент — то же самое можно заранее назначить
  на клавишу/жест в своём рабочем столе (`momentum4 disable --yes` — обычная команда
  оболочки, без интерактивных вопросов при заданном `--yes`).
- **AALL сам не проверяет и не чинит speech-dispatcher/Orca.** Если после
  перезапуска WirePlumber (единственный момент, когда это в принципе может произойти)
  диктор замолчал сам по себе — это отдельная, не специфичная для AALL проблема
  перезапуска аудио-стека; перезапустите speech-dispatcher или сессию рабочего стола
  обычным для вашей системы способом.
- Все длинные операции (`install --yes`, `enable --yes`, `disable --yes`,
  `uninstall --yes`) печатают отчёт **после** выполнения — что сделано, что не
  удалось (если что-то не удалось) и что делать дальше — а не просто молча завершаются.

Замечание про язык: вывод CLI и сообщения демона по умолчанию на английском;
для русского: `momentum4 config set general.language ru` (см. «Настройка»).
Английская версия этого файла — `README.md`.

## Известные ограничения

- Собственный обратный микрофонный канал для aptX Adaptive не входит в это API
  Bluetooth-профиля — во время звонка используется обычный HFP-профиль (mSBC/CVSD),
  не Adaptive; это ограничение самого Bluetooth-профиля A2DP+HFP, а не этого проекта.
- Плагин собирается и проверяется под одну конкретную версию PipeWire за раз
  (см. «Требования») — после обновления дистрибутива, если версия PipeWire
  изменилась, плагин нужно пересобрать; если версия не совпадает, WirePlumber
  автоматически загружает свои штатные плагины вместо наших (см. `momentum4 doctor`),
  и звук не пропадает, просто Adaptive временно недоступен.
- Только Linux x86_64; на других архитектурах не проверялось.
- Цифры задержки в документации проекта — грубые оценки на конкретном железе автора,
  а не гарантии: реальная задержка зависит от вашего Bluetooth-адаптера, наушников и
  конфигурации графа PipeWire.
