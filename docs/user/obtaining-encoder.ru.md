# Откуда взять модуль энкодера aptX Adaptive

English version: `docs/user/obtaining-encoder.md`.

Momentum4 не поставляет и не может поставлять файл кодека. Это проприетарный
модуль Qualcomm, часть прошивки конкретных Android-телефонов на Snapdragon
855/865/888 и новее. Найдите его сами в прошивке своего устройства (или
телефона, к которому у вас есть законный доступ) и укажите путь программе.

Юридическая оговорка: файл принадлежит Qualcomm и производителю телефона.
Momentum4 читает его только локально, на вашей машине, для собственного
воспроизведения звука; файл никуда не передаётся и не распространяется.
Соблюдение лицензии прошивки — ответственность того, кто её скачивает и
использует. Не публикуйте и не пересылайте этот файл третьим лицам.

## Что искать

Имя файла: `capi_v2_aptX_CLHDADV_Encoder.so`.
Путь внутри образа прошивки обычно такой:
`vendor/lib/rfsa/adsp/capi_v2_aptX_CLHDADV_Encoder.so`.

Это не обычная ARM-библиотека, а прошивка звукового DSP (Hexagon), поэтому
она лежит отдельно от привычных `/system/lib64` и `/vendor/lib64`.

## Шаг 1. Скачайте прошивку своего телефона

Возьмите официальный пакет прошивки (OTA-архив или fastboot-пакет) с сайта
производителя вашего устройства, либо публичный дамп прошивки с открытого
зеркала (например, репозитория с "деревом файлов" дампа на GitHub/GitLab —
там образ уже распакован постранично, и можно скачать один файл, не грузя
весь образ). Нужна прошивка устройства на Snapdragon 855 или новее,
поддерживающего aptX Adaptive.

## Шаг 2. Достаньте раздел с ADSP

Формат образа зависит от производителя, обычно один из:

- `payload.bin` (пакеты Google/AOSP-based OTA) — распакуйте инструментом
  `payload-dumper-go` или `payload_dumper` (Python), получите `vendor.img`.
- `super.img` (динамические разделы) — распакуйте `lpunpack`, дальше внутри
  ищите `vendor.img`.
- `new.dat.br` (старый формат Android sparse) — сначала `brotli -d`, затем
  `sdat2img.py`.
- Сам `vendor.img`/`system.img` может быть `ext4` (`simg2img` в обычный
  образ, дальше монтировать read-only или доставать файлы через `debugfs -R`)
  или `erofs` (доставайте через `fsck.erofs --extract=out/` или `7z x`,
  современные версии 7-Zip понимают EROFS).

## Шаг 3. Найдите файл и проверьте хэш

Внутри распакованного `vendor` найдите:

```
find . -iname 'capi_v2_aptX_CLHDADV_Encoder.so'
```

Посчитайте sha256:

```
sha256sum capi_v2_aptX_CLHDADV_Encoder.so
```

Сверьте с известными хэшами в `data/capi-sha256.txt` в этом репозитории.
Если хэш совпал со строкой, помеченной `LOADER-TESTED` — этот файл проверен
и точно работает с нашим загрузчиком. Если хэш неизвестен — программа
откажется его использовать без явного флага `--force` (см. ниже), потому
что несовместимый ABI может привести к падению helper-процесса (на звук
это не влияет: если модуль не запустится, включится обычный aptX HD).

## Шаг 4. Укажите файл программе

```
momentum4 setup --capi /путь/к/capi_v2_aptX_CLHDADV_Encoder.so
```

Программа проверит, что это Hexagon-ELF (`EM_HEXAGON`), сверит sha256 со
списком известных и скопирует файл в `~/.local/share/momentum4/capi/`.
Если хэш не из списка — команда завершится ошибкой; чтобы всё равно
использовать файл на свой риск, добавьте `--force`.

## Если не получилось

Ничего страшного: без этого файла aptX Adaptive просто не включится, и
телефон/наушники продолжат работать на обычном aptX HD — это штатный,
проверенный режим, звук не пропадёт.
