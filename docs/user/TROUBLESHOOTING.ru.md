# Диагностика

English version: `docs/user/TROUBLESHOOTING.md`.

Первый шаг почти всегда один:

```
momentum4 doctor
```

Это команда только для чтения — она ничего не меняет и не перезапускает. Каждая
строка `[WARN]` — конкретная проблема с объяснением, что делать. `[OK]`/`[--]` —
всё в порядке/нормальное отсутствие ещё не установленного компонента.

## Наушники подключились, но кодек не Adaptive

1. `momentum4 doctor` — проверьте строку про DSP-модуль (sha256 известен?) и про
   версию PipeWire/плагин (`wp-env`, "версия совпадает"?).
2. Если DSP-модуля нет — это ожидаемо: без него Adaptive не включается, а наушники
   работают на обычном кодеке. См. `docs/user/obtaining-encoder.md`.
3. Если версия PipeWire не совпадает с той, под которую собран плагин — пересоберите
   плагин (`make module && make install`) под установленную у вас версию PipeWire.
4. Если ваши наушники — не Sennheiser Momentum 4 и не откликаются на фильтр
   `allow-devices = adk-stereo` — попробуйте временно `allow-devices = any` в
   `[adaptive]` (после чего PipeWire предложит Adaptive любому совместимому
   приёмнику) или явно перечислите MAC-адрес(а).

## `doctor` пишет, что плагин собран и на месте, но `aptx_adaptive` не появляется у WirePlumber

Скорее всего дело в `[paths] spa-system-dir` — это путь к штатным (не нашим)
плагинам `spa-0.2` вашего дистрибутива, определяемый при сборке демона из
`pkg-config --variable=plugindir libspa-0.2`. `momentum4 wp-env` (запускается
автоматически перед стартом WirePlumber через наш overlay) сознательно **не
трогает** `SPA_PLUGIN_DIR`, если этот путь пуст или не существует — потому что
подмена `SPA_PLUGIN_DIR` только нашим каталогом (без системного) валит
WirePlumber SIGSEGV на старте (он теряет доступ к штатным `support.*`-плагинам).
Проверьте:

```
momentum4 config show | grep spa-system-dir
pkg-config --variable=plugindir libspa-0.2
```

Если вторая команда что-то печатает, а первая — пусто или другой путь, задайте
его явно в `momentum4.conf`:

```
[paths]
spa-system-dir = /usr/lib/x86_64-linux-gnu/spa-0.2   # ваш путь
```

и перезапустите WirePlumber (`momentum4 enable` сделает это сама). Если
`pkg-config --variable=plugindir libspa-0.2` тоже ничего не печатает — у вас,
вероятно, не установлен пакет `libspa-0.2-dev`/`pipewire-dev` (см.
«Сборочные зависимости» в README.md); соберите `make daemon`/`make install`
заново после установки нужного пакета.

## Пропал звук вообще (не только Adaptive)

```
momentum4 disable --yes
```

Откатывает нашу часть и перезапускает WirePlumber — после этого звук должен
вернуться на обычный кодек. Если и это не помогло — проблема не в momentum4, а в
самом PipeWire/WirePlumber/BlueZ; посмотрите `journalctl --user -u wireplumber -u pipewire`.

## Экранный диктор замолчал после `enable`/`disable`

Это редкий побочный эффект самого перезапуска WirePlumber (не специфичный для
momentum4 — то же самое иногда происходит после ручного `systemctl --user restart
wireplumber`). Momentum4 сознательно не пытается чинить speech-dispatcher/Orca —
перезапустите speech-dispatcher или сессию обычным способом для вашего рабочего стола.

## Помощник (qemu-hexagon) не запускается / часто перезапускается

```
momentum4 stats
momentum4 log -n 200
```

`stats` покажет метрики моста (недоборы буфера, задержка энкодера); `log` — последние
сообщения. Частые перезапуски обычно означают, что либо DSP-модуль не тот
(проверьте sha256 через `doctor`), либо не хватает прав реального времени
(`ulimit -r`, см. `[helper] rt-priority` в `momentum4 config defaults`) — это не
критично для звука, просто мост будет работать без приоритета реального времени.

## Сборка не находит clang с поддержкой Hexagon

Сообщение об ошибке при сборке `loader` называет конкретные версии, которые
проверяются (`clang-14` .. `clang-19`, затем просто `clang`), и что делать. Если у вас
установлен clang другой версии по нестандартному пути — укажите его явно:

```
meson configure build-top -Dhexagon_cc=/путь/к/clang
```

## Нет сети / нет доступа к download.qemu.org для `make qemu`

Сборка своего `qemu-hexagon` — необязательный шаг. Системный пакет
`qemu-user-static`/`qemu-user` (если он предоставляет `qemu-hexagon`) тоже подходит,
просто медленнее (выше загрузка ядра на пакет). Укажите путь к нему в
`[helper] qemu`, если он не там, где `momentum4` ищет по умолчанию (`doctor` подскажет).
