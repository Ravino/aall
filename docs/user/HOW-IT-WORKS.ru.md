# Как это устроено (коротко, для любопытных)

English version: `docs/user/HOW-IT-WORKS.md`.

## Кодек

aptX Adaptive — кодек компании Qualcomm. Его энкодер — не обычный код для основного
процессора, а модуль для отдельного сигнального процессора (Hexagon ADSP), который
на телефонах Qualcomm встроен рядом с основным процессором именно для звука/связи.
Такой модуль есть в прошивке телефонов на Snapdragon 855 и новее (там, где Adaptive
поддерживается аппаратно).

Поскольку это не обычный x86/ARM-код, а код для другого, специализированного
процессора, его нельзя просто слинковать и вызвать напрямую на обычном компьютере.
Momentum4 решает это эмуляцией: маленькая программа-загрузчик исполняется под
`qemu-hexagon` (пользовательская эмуляция, см. README.md «QEMU»), сама загружает
DSP-модуль как разделяемую библиотеку внутри эмулируемого процесса и вызывает его
API кодирования. Со стороны PipeWire это выглядит как обычный внешний
процесс-помощник: PCM-аудио заходит, сжатые кадры aptX Adaptive выходят, с задержкой
в единицы миллисекунд.

## Путь звука

```
приложение → PipeWire → SPA-плагин bluez5 (наш кодек aptx_adaptive)
           → помощник (qemu-hexagon + DSP-модуль) → сжатые кадры
           → AVDTP (Bluetooth A2DP) → наушники
```

Плагин регистрирует кодек `aptx_adaptive` в списке кодеков, которые PipeWire
предлагает через AVDTP при подключении наушников. Если наушники поддерживают
Adaptive и приняли конфигурацию — PipeWire начинает кодировать этим путём вместо
штатного aptX HD/SBC.

## Почему отдельный процесс-помощник, а не часть самого WirePlumber

Эмуляция QEMU генерирует исполняемый код на лету (JIT) — ей нужно право отметить
память исполняемой (`mprotect(PROT_EXEC)`). Штатный юнит WirePlumber в современных
дистрибутивах запускается с усиленной защитой (`MemoryDenyWriteExecute=yes`), которая
именно это запрещает — правильно для самого WirePlumber, но несовместимо с
JIT-эмуляцией внутри него. Поэтому помощник — отдельный systemd `--user`-юнит без
этого ограничения, а сам WirePlumber остаётся с полной штатной защитой.

## Почему фильтр по умолчанию — не по имени устройства

Разные наушники на чипах Qualcomm могут заявлять поддержку Adaptive, но с разными
собственными параметрами (задержка, частота дискретизации, битрейт). Momentum4 знает
только один набор параметров, проверенный на Sennheiser Momentum 4 (по факту — типовой
заводской профиль возможностей "stereo headset", который декларируют многие чипы Qualcomm, а не что-то специфичное только для
одной модели). Поэтому по умолчанию кодек предлагается только приёмникам с таким же
отпечатком возможностей (`allow-devices = adk-stereo`) — не по названию устройства,
а по тому, что оно реально заявляет в своих возможностях AVDTP. Для наушников
другого производителя с другим набором параметров этот же кодек может воспроизводить
тишину или искажённый звук — отсюда осторожность по умолчанию, с явной возможностью
её отключить (`allow-devices = any` или список MAC), если вы точно знаете, что делаете.

## Защита от несовпадения версии PipeWire

Плагин собирается и проверяется под одну конкретную версию PipeWire. При запуске
WirePlumber сверяет версию установленного плагина с версией самого PipeWire —
если они не совпадают (или плагин вообще не установлен), WirePlumber загружает свои
штатные плагины, как будто momentum4 не установлен вовсе. Наушники в этом случае
используют обычный кодек — тишины не бывает.
